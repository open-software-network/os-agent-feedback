Epode gives companies a permissioned communication channel with the **independent agents used by
their customers**. Learn what customers wanted, whether the product worked, where they struggled, and
which evidence-backed change matters next. You instrument your product; customers do not install an SDK,
create an Epode account, or identify their agent.

## The mental model

<Steps>
  <Step title="Your product responds">
    Epode's server-side SDK adds a short-lived, write-only feedback contract to selected successful responses.
    Telemetry never delays the response, and HTTP Ask once never waits on Epode. The SDK emits a subject-bound receipt locally; Epode Companion verifies it and resolves the remembered decision before asking or reporting.
  </Step>
  <Step title="Your customer's agent uses the result">
    The agent performs the customer's real task using your API, page, or MCP tool.
  </Step>
  <Step title="The agent reports what happened">
    A feedback-aware HTTP runtime or MCP client can send one bounded report containing a summary,
    impact, findings, confidence, and any workaround.
  </Step>
</Steps>

<Note>
Epode does not identify agents or invent customer identity. Optional customer and session references come
from verified identifiers, product-owned anonymous references, and server-proven journeys—not names, emails,
prompts, task content, caller fields, or agent claims. `customerRef` remains only the compatible Ask-once
subject and must equal `accountRef` when both are present; new integrations add `accountRef`, `userRef`, and
`anonymousRef` as private, nonblocking telemetry.
</Note>
